Practical scheduling guide

Find a meeting time people can actually attend

A city-to-city time conversion is only the start. A useful meeting plan also checks the local date, each person's working hours, and the whole meeting—not just its first minute.

Start with the meeting date

Choose a reference city and the date you want to explore there. The reference city gives “Tuesday” a clear meaning. A time late on Tuesday in Los Angeles can already be Wednesday in Tokyo, so every participant needs a date as well as a clock time. MeetAcross displays both for each location.

Use the date of the meeting rather than today's offset. Daylight saving changes can alter the difference between cities, and different countries can change clocks on different weekends. A slot that works this week may shift by an hour next week. The Tokyo, London, and New York example shows this problem in October and November 2026.

Give each city its real working window

Add up to four cities and set local start and end times for each. The initial window is 09:00–17:00, with weekdays only enabled. Those defaults are assumptions you can edit; they are not evidence of anybody's availability. A teammate working 07:00–15:00 needs their own window.

Weekday checks use the local date in each city. The planner does not know public holidays, annual leave, lunch breaks, existing calendar events, or personal commitments. Confirm those separately. Work windows must end after they start on the same local day; overnight shifts are not supported. Choose a daytime window or plan that case directly with the participant.

Check the full duration

Choose 30, 60, 90, or 120 minutes before comparing results. A 16:30 start fits a 30-minute meeting in a window ending at 17:00, but a 60-minute meeting would run beyond it. A slot counts as within working hours only when the complete meeting fits each relevant window.

The planner considers starts every 30 minutes across the reference date. This makes the list manageable, but it does not test every possible minute. If you need a 09:15 start, use a nearby result to understand the overlap and confirm the exact time in your calendar. Shortening a meeting can create a usable overlap where a longer one would not fit.

When there is no shared window

An empty overlap is a useful result. It means none of the tested 30-minute-grid starts satisfies every selected working window for that duration. A narrow overlap at another minute, such as 09:05, may still exist; the planner does not test it. Check exact timing before concluding that no meeting is possible. Do not silently widen someone's window to make a result turn green. Ask whether an exception is acceptable and describe the burden explicitly: “This would be 07:00 for you; would a short call work?”

For recurring teams spread across distant regions, consider rotating the inconvenience, holding two smaller calls, or replacing a status meeting with a written update. Recheck any recurring arrangement on both sides of upcoming clock changes. Downloading one calendar event does not create a recurring series.

Read offsets and clock-change days carefully

Each displayed UTC offset belongs to that place at that instant. A reference day can contain 23, 24, or 25 hours when local clocks change. MeetAcross follows the actual elapsed day rather than assuming every day is 24 hours. If the reference date's midnight is missing or occurs twice under a local time rule, the planner rejects that reference date instead of choosing an interpretation silently.

Calculations use your browser's time-zone data. The IANA Time Zone Database describes the underlying rules and how software vendors distribute updates. Keep your browser and operating system updated, particularly for places with recently changed rules.

Share the plan, then confirm it

A share link stores planner settings in its URL fragment. Anyone with the link can see the cities, date, working windows, and duration. The planner does not ask for names or email addresses. You can also download an ICS event using UTC start and end times, based on the iCalendar format.

The download adds no attendees and sends no invitations. Import the file into your calendar, check the displayed local time, and invite people through your normal calendar workflow. Confirm the date, duration, and any outside-hours exception with them before treating the meeting as agreed.
