A more useful export

Fit the image to the job

A picture can have suitable dimensions and still exceed an upload limit. It can also be a small file with too few pixels for its intended display. ImageFit Desk lets you handle those two requirements separately: first choose the pixel bounds, then select an output format and, where available, try a file-size target. Keep the original so you can make another export without repeatedly encoding the last result.

1. Read the receiving site's requirements

Before editing, check the allowed formats, maximum width and height, and maximum file size. A requirement such as “under 200 KB” describes the encoded file, not the size of the image after a browser decodes it. This tool treats one KB as 1,000 bytes. Some applications use 1,024 bytes for a similarly labelled unit, so compare exact byte counts when the boundary matters. Leave a little room below a strict limit rather than aiming for its exact edge.

2. Load a supported static image

Choose a PNG, JPEG or WebP image. ImageFit Desk accepts files up to 10 MiB, with neither dimension above 8,192 pixels and no more than 16 million pixels in total. These are separate limits: a 5,000 × 4,000 image exceeds the pixel limit even though each side is below 8,192. Animated PNG and WebP, GIF, HEIC and SVG are outside this tool's scope. Convert those through an appropriate application before using this workflow.

3. Set bounds without stretching

Maximum width and height define a box that the result must fit inside. The tool preserves the original aspect ratio, so one dimension may finish below your chosen maximum. For example, a 4,000 × 3,000 photo inside a 1,200 × 800 box becomes about 1,067 × 800, rather than a stretched 1,200 × 800 image. ImageFit Desk does not upscale smaller sources. It also does not crop a wide photo into a square; prepare that crop separately if the destination requires one.

4. Match the format to the content

For a photograph without transparency, JPEG is a practical starting point. WebP can be useful when the destination accepts it, including images with transparent areas. PNG is often suitable for crisp interface captures, flat colour and transparency. The format comparison explains the tradeoffs. A transparent image exported as JPEG gets a white background, so check how that change affects a logo or a cutout.

5. Treat a size target as a search

For JPEG or WebP, a target asks the tool to search encoding quality at the selected dimensions. It does not silently keep shrinking the image until the limit is met. A detailed photograph may remain too large even at low quality. If the tool cannot reach your target, reduce the pixel bounds, choose a different accepted format, or relax the budget. A low-quality export that technically fits may be less useful than a smaller but clearer picture.

PNG is re-encoded without a quality slider or a promised target size. Re-encoding alone may produce a larger file. Reduce its dimensions if necessary and inspect the reported output size before saving.

6. Check the result, then download

Review faces, small text, gradients and transparent edges at the size people will actually view them. Check the output dimensions and byte count, then download and test the file in the receiving application. Renaming a filename extension does not change a format. If a destination rejects the export, confirm its requirements rather than repeatedly converting the same file.

Understand the privacy boundary

The image processing happens in your browser tab; the selected image is not uploaded by this tool. Canvas export does not preserve source metadata, and browsers may transform colours while decoding or encoding. This is not a forensic guarantee that every identifying detail has disappeared. Review visible content and use a dedicated workflow when exact colour or verified sanitisation is required.
