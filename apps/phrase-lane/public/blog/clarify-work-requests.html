WORK REQUESTS

Clarify a work request before translating it

PhraseLane editorial draft · Updated 5 October 2026

AI-assisted draft. Human editorial review has not been completed. Review examples and translated output before using them in real work.

Turn a vague work instruction into a specific action, scope and confirmation question.

Identify the ambiguity first

“Fix the presentation” may refer to formatting, wording, numbers or all three. Translation cannot supply a missing decision. Before translating, describe the observable change and the part of the work that needs it.

Compare “Can you improve this?” with “Could you shorten the introduction to two paragraphs and keep the pricing table unchanged?” The second request gives the recipient a useful boundary and lets you check the resulting translation.

Ask one clear question

If you are receiving a vague request, ask for the decision that blocks progress. “Do you want only the layout changed, or should I also revise the wording?” is easier to answer than a list of ten unrelated questions. You can ask the next question once the scope is clear.

Use a small, structured message

I can update the presentation. To confirm the scope: should I revise only the layout, or also the wording? Please tell me which version of the file to use. I will confirm the delivery time after reviewing it.

Keep assumptions visible

If you must begin before an answer arrives, tell the requester the assumption: “I will start with the layout of the current shared draft. Please confirm before I change the pricing text.” Only proceed where your role and the task allow that choice. A translation does not create authority to change a customer’s commitments.

Check the translated question

Review whether the choices stayed separate and whether “can” became “will.” Check numbers, version labels and exclusions. If you cannot judge the target-language nuance, ask a capable reviewer or the recipient for confirmation rather than treating a fluent sentence as proof of correctness.
