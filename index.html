Behind this demo

単一HTMLで作る、カフェサイトの設計。

このページは、お店の情報を見つけやすく並べるためのWeb制作サンプルです。HTML・CSS・JavaScriptと図版をひとつのファイルに収めています。カフェの紹介文、メニュー、営業時間、地図はデモ用で、実在するお店の体験談や営業情報ではありません。以下では、実装している仕組みと、別のお店に合わせる際の変更点を説明します。

1. 来店前に必要な情報から構成する

ヒーローで雰囲気を示した後、店舗紹介、メニュー、営業時間とアクセス、お問い合わせを並べています。ページ内リンクはセクションのidに対応します。見出しはh1からh2、h3へ階層を付け、営業時間には表の見出しセルを使っています。本文へ直接移動できるスキップリンクも、キーボードで操作する利用者のための入口です。

お店の内容へ変更するときは、見た目の文章だけでなく、ページのタイトルと説明文、画像の読み上げ用の説明、営業時間表、地図の注記も一緒に更新してください。特にこのサンプルの地図は架空の図版です。実際の場所への案内として使う場合は、正しい位置と経路へ差し替える必要があります。

2. SVGの図版を、外部画像なしで表示する

コーヒーカップ、クロワッサン、店内イメージはHTML内のSVGで描いています。線や形、グラデーションから構成されるため、写真ファイルの取得は不要です。共通の図形はsymbolやuseで再利用しています。写真のような記録ではなく、デザインの雰囲気を伝えるイラストとして使用しています。

図版を変更するときは、画面に合わせて拡縮するviewBoxを保ち、説明が必要な図にはtitleとaria-labelledbyを付けます。文字を含むSVGは、スマートフォンで縮小したときに読めるかを確認してください。実店舗の写真へ置き換えるなら、自分に掲載権限がある画像を使い、画像サイズや説明文も調整します。

3. スマートフォンのメニューとフォーカス

幅760px以下では、JavaScriptがイベントを設定した後にナビを折りたたみます。ボタンのaria-expandedは開閉状態に合わせて切り替わります。Escapeキーで閉じた場合はボタンへフォーカスを戻し、ページ内リンクを選んだ場合は移動先へ渡します。メニューの外をクリックしたときや、PCの幅へ戻ったときも閉じます。

実装を変更したら、開く・閉じるだけでなく、Tabキーでリンクへ移動できるか、Escapeの後に操作位置が分かるか、リンクを選んだ後に非表示のナビへフォーカスが残らないかを確認します。JavaScriptを無効にした場合も、通常のナビリンクと本文を読める構成にしています。

4. 動きを減らす設定にも対応する

スクロール表示にはIntersectionObserverを使い、画面に入った要素を一度だけ表示します。OSやブラウザがprefers-reduced-motion: reduceを示している場合は、監視による表示演出を開始しません。閲覧中にその設定が変わった場合も、対象の内容を表示したままにします。

動きの設定に応じた表示を変更するときは、アニメーションを省いた結果、文字やボタンまで消えないことが大切です。演出は情報を読む条件ではありません。通常表示、低モーション、JavaScript無効のそれぞれで本文へアクセスできるかを確認してください。

5. お問い合わせは、送信フォームとは別の仕組み

現在の問い合わせボタンはdialogでデモの案内を表示します。名前やメールアドレスを入力して送信する機能はありません。HTML内のCONTACT_EMAILへ受信できる宛先を設定すると、ボタンはmailto:リンクになります。これは利用者のメールアプリを開く動作で、サイトがメールを配送する仕組みではありません。

予約や問い合わせを実際に受け付ける場合は、宛先を差し替えるだけで受付体制が完成するわけではありません。送信手段、受付時間、入力情報の扱い、エラー時の案内を実際の運用に合わせて用意してください。このサンプルに入力フォームがあるような説明を加えると、動作と案内が一致しなくなります。

6. HTML変更後は、CSPを再生成する

公開用のビルドでは、inlineのJavaScriptとCSSの内容からSHA-256を計算し、許可する内容をCSPヘッダーへ記載しています。HTMLを変更した後に古いヘッダーを使うと、変更したJSやCSSが拒否される可能性があります。node scripts/build-static.mjsでHTMLとヘッダーを同時に生成する必要があります。

CSPは読み込むリソースを制限する防御のひとつです。第三者サービスを追加する場合は、そのサービスへの通信とデータの扱いも確認します。ヘッダーが設定されていることだけで、すべての攻撃や広告審査への適合が保証されるわけではありません。

実店舗用へ変更する順番

  1. 店舗情報・価格・営業時間・地図を正しい内容へ置き換え、サンプル表記との整合を確認する。
  2. 掲載権限のある図版を選び、読み上げ用の説明とページのタイトルを更新する。
  3. 連絡・予約の実際の受付方法を用意し、そのデータの扱いを説明する。
  4. PC、スマートフォン、キーボード、低モーション、JavaScript無効時を確認する。
  5. 再ビルドし、公開先のHTTPヘッダーと主要操作を確認する。

About this project

このサイトについて。

Firstmakeは、カフェをテーマにしたWeb制作サンプルと、その構成・操作の解説を公開するプロジェクトです。KOMOREBIは架空の店名です。実在する店舗の公式サイト、飲食店の予約サービス、利用者の実体験に基づくレビューではありません。

公開リポジトリはGitHubのfmfmstars-beep/Firstmakeです。サイトの不具合や改善提案、掲載内容・プライバシーに関する連絡は、GitHubの意見受付フォームへ送れます。GitHubへのログインが必要で、投稿は公開されます。パスワード、口座情報、本人確認書類、非公開にしたい個人情報は投稿しないでください。

Privacy

プライバシーについて。

更新日：2026年10月3日。この説明はFirstmakeの公開ページに適用されます。

現在のページとホスティング

このページのJavaScriptは、ナビゲーション、表示演出、お問い合わせのデモ案内に使っています。ページ独自のJavaScriptによるCookieやブラウザストレージへの保存、入力フォームの送信、広告・アクセス解析の外部スクリプト読み込みは実装していません。

ページの配信にはCloudflareを使用しています。配信やセキュリティのため、IPアドレスやリクエスト等の技術情報がホスティング事業者で取り扱われる場合があります。Cloudflareによる取り扱いはCloudflareのプライバシーポリシーをご確認ください。

連絡と外部リンク

お問い合わせのデモ表示は情報を送信しません。意見受付フォームのリンクを開くとGitHubへ移動し、そのサービスの規約・プライバシーの説明が適用されます。投稿内容は公開されるため、個人情報を含めずにご連絡ください。

Google広告を導入する場合

AdSenseによる広告掲載を準備していますが、現在このページに広告配信スクリプトはありません。サイト所有権確認用のメタタグと広告販売者情報のファイル自体は、ブラウザで広告を読み込む機能ではありません。

Google広告を導入した場合、Googleなどの第三者配信事業者はCookieを使用して、このサイトや他のサイトへの過去のアクセスに基づく広告を配信することがあります。Googleの広告Cookieにより、Googleおよびそのパートナーが利用者に応じた広告を表示できるようになります。パーソナライズド広告の設定はGoogleの広告設定で変更できます。第三者配信事業者の広告Cookieの設定についてはAboutAdsの選択ページも参照できます。

広告の導入前に、実際の配信事業者、必要な同意取得の方法、広告コードとの動作を確認し、この説明を更新します。Googleの情報の扱いについてはGoogleの広告に関する説明をご確認ください。現時点で、広告掲載・審査承認・収益の発生を示すものではありません。
